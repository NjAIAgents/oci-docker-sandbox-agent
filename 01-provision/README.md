# Post 1 — Claiming Your Free OCI ARM VM: The Right Way

> Part of the series: **Running Autonomous Agents on OCI Free Tier**
> [Read on Medium](#) <!-- TODO: replace with live URL -->

OCI's Always Free tier includes 4 ARM OCPUs and 24 GB RAM. That is a real machine — enough to run a full multi-agent system at zero cost. The problem is getting it. Capacity is constrained and provisioning attempts fail silently on whichever availability domain is full at that moment. Most people give up.

This post gives you a retry loop that rotates across all three availability domains automatically, classifies every failure type, and keeps going until capacity opens up. It runs unattended. You come back to a running VM.

---

## What this does

`setup.sh` is the entry point. Run it once, answer a few prompts, and it:

1. Checks that `terraform`, `oci` CLI, and `jq` are installed and working
2. Auto-detects your tenancy OCID and region from `~/.oci/config`
3. Verifies OCI API connectivity with a live call
4. Fetches all availability domains in your region from the OCI API (no manual lookup)
5. Prompts for the remaining config values, all with sensible defaults
6. Renders four Terraform files into `01-provision/` (or a target directory you specify)

`provision.sh` (generated by setup.sh) does the actual provisioning:

1. Loops across AD1, AD2, AD3 attempting `terraform apply` in each
2. Classifies the error type on each failure
3. Handles rate limits and OCI internal errors with targeted backoff and one automatic retry
4. Exits immediately (with a clear message) on non-recoverable errors (quota, auth, 403, bad params)
5. Logs everything timestamped to `oci-provision.log`

## Prerequisites

| Tool | Purpose | Check |
|------|---------|-------|
| `terraform` | Provision OCI resources | `terraform version` |
| `oci` CLI | API calls + auth | `oci --version` |
| `jq` | Parse JSON from OCI API | `jq --version` |
| `~/.oci/config` | API key authentication | `cat ~/.oci/config` |

Your `~/.oci/config` must have `tenancy`, `region`, `user`, `fingerprint`, and `key_file` populated. Run `oci setup config` if it does not exist yet.

## Quick start

```bash
# From repo root:
make provision

# Equivalently:
cd 01-provision && bash setup.sh
```

Answer the prompts (all have defaults — just hit Enter if the detected values are correct), then:

```bash
cd 01-provision
terraform init       # first time only
bash provision.sh    # runs until capacity opens
```

Monitor progress in a second terminal:

```bash
tail -f 01-provision/oci-provision.log
```

## What setup.sh generates

| File | Generated | Notes |
|------|-----------|-------|
| `provision.sh` | Always | The retry loop script |
| `terraform.tfvars` | Always | Your config values baked in |
| `main.tf` | Only if no existing `main.tf` | Full OCI Terraform scaffold |
| `variable.tf` | Only if no existing `main.tf` | All 7 variable declarations |

If a `main.tf` already exists in the target directory, setup.sh skips generating `main.tf` and `variable.tf` and prints a patch notice listing the variable blocks you may need to add manually.

## How provision.sh works

provision.sh rotates across your three availability domains. For each attempt:

1. Runs `terraform destroy -auto-approve` to clean any partial state (non-fatal if it fails)
2. Runs `terraform apply -auto-approve -var "availability_domain=<AD>"`
3. Classifies the result

### Exit codes

| Code | Meaning | Action |
|------|---------|--------|
| 0 | SUCCESS — instance provisioned | Fill `VM_PUBLIC_IP` in `.env`, run `make ssh` |
| 2 | Quota reached — already at Always Free limit | Check https://cloud.oracle.com/limits |
| 3 | Auth failure (401) | Fix `~/.oci/config`: key path, fingerprint, user OCID |
| 4 | Authorization denied (403) | Add compute IAM policy for your OCI user/group |
| 5 | Invalid parameter (400) | Check `terraform.tfvars`: compartment OCID, region |

Exit codes 2-5 are **fatal** — provision.sh stops immediately with a remediation hint. There is no benefit to retrying these; they require human action.

Capacity failures and unknown transient errors rotate to the next AD and eventually the next round. The loop runs indefinitely until you get a VM or hit a fatal exit.

### Error taxonomy

| Error class | OCI signal | Behavior |
|-------------|-----------|----------|
| `capacity` | "Out of host capacity" / InsufficientServiceCapacity | Rotate AD |
| `limit` | LimitExceeded / "service limit" | Fatal exit 2 |
| `auth` | NotAuthenticated / 401 | Fatal exit 3 |
| `forbidden` | Forbidden / 403 / NotAuthorized | Fatal exit 4 |
| `invalid` | InvalidParameter / 400 | Fatal exit 5 |
| `ratelimit` | TooManyRequests / 429 | Sleep 2x round, retry same AD once, then rotate |
| `internal` | InternalError / 5xx | Sleep 120s, retry same AD once, then rotate |
| `unknown` | Anything else | Treat as transient, rotate AD |

## Directory structure (after setup.sh runs)

```
01-provision/
├── setup.sh                  # run this first
├── templates/
│   ├── provision.sh.tpl      # source template for the retry loop
│   ├── main.tf.tpl           # source template for Terraform resources
│   ├── variable.tf.tpl       # source template for variable declarations
│   └── terraform.tfvars.tpl  # source template for variable values
├── provision.sh              # generated — run after terraform init
├── main.tf                   # generated — OCI resources
├── variable.tf               # generated — variable declarations
├── terraform.tfvars          # generated — your config values
└── oci-provision.log         # generated — timestamped run log
```
